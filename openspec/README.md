# OpenSpec

Product and architecture changes should be specified before implementation.

Recommended lifecycle:

```text
proposal -> spec -> implementation -> test -> review -> PR
```

Each non-trivial change should state:
- problem and user value
- scope / non-goals
- acceptance criteria
- architecture/API impact
- test plan
- rollout or migration concerns

The exact OpenSpec tooling/version will be pinned when the DevContainer technology stack is finalized.
